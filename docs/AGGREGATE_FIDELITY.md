# Reproducible aggregate reconstruction evidence

The new [72-case evidence bundle](../evidence/independent/aggregate-fidelity/run-01/index.json)
executes the current reference transform against the true sum of source signals.
It includes raw source arrays, intermediate coefficient/reconstruction arrays,
error vectors, per-channel and combined metrics, frozen source and a SHA256
manifest. [The verifier](../tools/check_aggregate_fidelity.py) regenerates every
input and recomputes every case and summary; hashes alone are insufficient.

## Declared experiment

The matrix is two seeds `(1000,1001)`, three signal families, three profiles
and batch sizes `(1,12,14,16)`: 72 cases. All signals contain two synchronized
240-sample channels in arbitrary integer counts. Triangle, sparse-pulse and
step-plus-bounded-noise families are defined in `index.json` and generated by
integer/SHA256 operations. These are declared test inputs, not a sensor corpus
or a sample of independent physical deployments.

The profile supports, steps and capacities come from the current code:

| Profile | Retained coefficients | Step | Capacity |
|---|---:|---:|---:|
| pi0 | 240 | 8 | 16 |
| pi1 | 180 | 12 | 14 |
| pi2 | 120 | 16 | 12 |

There are **54 capacity-admissible cases** and **18 inadmissible diagnostic
cases**, reported separately. Capacity admissibility is not full protocol or
control certification. The tool rejects out-of-range source coefficients and
actual aggregate data wrap; it does not clip them. It performs signal-domain
arithmetic, not an encryption/decryption or hardware experiment.

## What is compared

Let `x=sum_i x_i`, and let `F` be the specified rounded integer transform. Define:

1. `y0 = inverse(sum_i F(x_i))`, using all 480 coefficients as a diagnostic;
2. `y1 = inverse(scatter(selected sum_i F(x_i)))`, before quantization;
3. `y2 = inverse(scatter(step * sum_i round(selected F(x_i)/step)))`, the
   reference aggregate reconstruction;
4. the sum of separately reconstructed, selected/quantized sources.

The exact vector identity is

`y2-x = (y0-x) + (y1-y0) + (y2-y1)`.

This separates integer-lifting aggregation, coefficient selection and
quantization in a declared order. Their squared errors include cross terms;
RMSEs and PRDs cannot be added. Full-support quantization is also retained as
a mathematical diagnostic and is explicitly not a valid 480-coefficient
single-polynomial action.

Metrics use the **true aggregate** as reference. PRD is
`100*sqrt(sum(error^2)/sum(reference^2))`; zero or cancelling reference energy
produces JSON `null` with `undefined_zero_reference_energy`, including cases
where error is nonzero. RMSE remains defined in integer counts. The summary
uses descriptive equal-case means; it supplies no confidence interval or
population-performance claim. Inspect each family/case before interpreting a
pooled mean, especially for sparse or cancelling sums.

## Reproduce and inspect

```bash
python tools/check_aggregate_fidelity.py --verify \
  evidence/independent/aggregate-fidelity/run-01
python tools/check_aggregate_fidelity.py --output runs/fidelity-new
python tools/check_aggregate_fidelity.py --verify runs/fidelity-new
python -m unittest discover -s tests -p test_aggregate_fidelity.py -v
```

Integer arrays must match exactly; recomputed floating metrics use a 1e-12
tolerance. Output directories cannot be overwritten. The frozen entry point
under the evidence bundle's `source/tools/` can verify the bundle if current
source later changes.

This supplements paper p.13 Eq.(25)/Table III with auditable aggregate-domain
evidence. It does **not** reproduce Table III, its mV/mA units or its 2.50% claim.
That requires the original trace corpus, scaling and transform conventions,
followed by evaluation at admissible batch sizes against the physical sum.
