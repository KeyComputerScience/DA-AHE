# Independent execution and verification

Original experiment artifacts are unavailable in this checkout. Everything added
by this change is an independent reimplementation. It is not a restoration of the author's original OMNeT++/Contiki-NG
project and does not validate the manuscript's historical numerical claims.
`evidence/independent/STATUS.json` records actual completed stages and limitations.

## 1. Canonical code and functional validation

Use Python 3.12 and a new virtual environment:

```bash
python -m pip install -e '.[dev]'
python tools/run_logged.py --output runs/tests -- python -m pytest -q
cmake -S embedded -B build/embedded -DDAAHE_MODULE_RANK=6
cmake --build build/embedded
ctest --test-dir build/embedded --output-on-failure
```

Checkout imports now redirect to `src/daahe/`; the previous duplicated root
modules are removed. No tests accidentally exercise a stale copied package.
The supplied test receipts include the actual exit status, stdout/stderr and
source snapshot at execution. They are records of an execution, not signatures
from an independent laboratory.

## 2. Real ML-DSA and aggregation behavior

The native provider used in this execution is liboqs 0.16.0 at upstream commit
`5a1a854b0dc9f2141bdc771c555ee60c37950183`, plus liboqs-python 0.16.0.1.

```bash
python -m pip install -r requirements-pq.txt
git clone https://github.com/open-quantum-safe/liboqs.git external/liboqs
git -C external/liboqs checkout --detach 5a1a854b0dc9f2141bdc771c555ee60c37950183
cmake -S external/liboqs -B build/liboqs -DBUILD_SHARED_LIBS=ON \
  -DOQS_BUILD_ONLY_LIB=ON -DOQS_MINIMAL_BUILD=SIG_ml_dsa_44 \
  -DOQS_USE_OPENSSL=OFF -DCMAKE_INSTALL_PREFIX="$PWD/external/oqs-install"
cmake --build build/liboqs --parallel 2
cmake --install build/liboqs
export OQS_INSTALL_PATH="$PWD/external/oqs-install"
export LD_LIBRARY_PATH="$OQS_INSTALL_PATH/lib:$OQS_INSTALL_PATH/lib64"
# macOS additionally uses DYLD_LIBRARY_PATH instead of LD_LIBRARY_PATH.
python -m pytest -q -m pq
python tools/run_logged.py --output runs/protocol-execution -- \
  python tools/run_protocol_trials.py --trials 20 --output runs/protocol
```

Trials generate fresh real-provider keys and encryption randomness; they use
synthetic waveforms, three participants and pi0/pi1/pi2 in rotation. Reports
include honest aggregation, a compromised-gateway ciphertext modification with
a valid transport MAC, durable replay rejection and actual synthetic aggregate
reconstruction errors. Private keys, epoch secrets and replay databases are
created in an automatically deleted private temporary directory, not published.
These twenty fresh-key trials are separate from the twenty network RNG seeds.
Host wall time is not an embedded CPU measurement. Zero observed failures do
not establish a rare-failure probability or cryptographic strength.

## 3. Paired network experiments and raw evidence

```bash
python tools/run_logged.py --timeout 10000 --output runs/campaign-execution -- \
  python tools/run_simulation_campaign.py --config simulation/config.json \
  --output runs/simulation
python tools/verify_simulation_campaign.py runs/simulation
```

The simulator is a new Python discrete-event model. Its explicit topology,
channel, traffic, processing, wire and energy assumptions are in the config and
`simulation/README.md`. They are not nRF52840 calibration measurements. The
controller uses the existing equations with an explicitly synthetic, uncertified
fixture. Every selected decision remains labeled uncertified. No new uniform
uncertainty certificate or physical-plant theorem is claimed.

A seed fixes method-independent topology, sampling opportunities and disturbance
trajectories. Semantic keyed random streams prevent an adaptive method from
shifting exogenous randomness by consuming a different number of random draws.
All methods receive causal telemetry generated by their own queues and outcomes.
Sampling skips, packet loss, report loss, accepted corrupted reports and verified
reports have distinct counters. Recovery is retained as right-censored if the
criterion is never met; there is no artificial timeout recovery value.

The verifier checks hashes, pairing/completeness and independently recomputes
metrics from raw records. Optional deterministic replay executes the simulator
again; see its `--help` and the small replay test. The optional longer paper-like
config is a prospective scenario, not a claim to implement INET/RPL or to have
executed the original paper experiment.

## 4. Firmware and physical measurements

See `firmware/README.md`. The delivered ELF/map/native execution belongs to an
independent bare-metal core microbenchmark. Its register setup, cycle/stack
boundaries, fixture callbacks, supported kernels and missing full-protocol
operations are explicit. Compilation is not device execution. Zero board samples
are reported until a physical serial capture is actually made.

The collector records literal serial bytes and binds them to a firmware build.
The verifier checks raw/build hashes, sequence and known-answer results. This
structural check cannot authenticate a physical device or substitute for operator
provenance, an external energy meter, calibration or complete firmware scope.

## 5. Security estimates and mathematical gates

Use the fixed official Lattice Estimator commit
`53da5982597709ba0fdf94ea37a84d822310fd84`; see `security/README.md` for the
SageMath command, timeout behavior and actual log schema. Costs are retained
per attack. A missing/failed attack, below-floor result or timed-out execution
is not replaced by the manuscript's target. Operation costs are heuristic
estimates under their declared attack models, not a hardness proof.

The selected k=6 tuple achieves a minimum of 136.475 bits across all seven
successful attacks. Its ciphertext is 7,168 bytes, compared with 4,096 bytes for
the legacy k=3 tuple. `security/DECODING_BOUND.md` documents a separate Sage
256-bit outward-interval proof using the implementation's exact finite CDT.
The 42-choice, one-fresh-batch adaptive union has log2 failure upper bound
-130.5101731584115. This is a joint random-key/fresh-noise statement under the
documented preauthorization assumptions, not a conditional guarantee for every
fixed key or an unlimited number of batches. The executed record is
`evidence/independent/decoding/k6-cdt-03/`.

`tools/check_reference_bounds.py` separately checks exact integer no-wrap
arithmetic for the supplied profiles. Its output remains uncertified: it does
not establish whole-batch Gaussian tails, complete workspace/airtime limits,
uniform control uncertainty, domain invariance or a useful fallback bound.
The original strict controller gates are not relaxed to make a demonstration
appear certified.

## 6. Archive and integrity checks

```bash
python tools/independent_manifest.py build --root runs
python tools/independent_manifest.py verify --root runs
```

Finish all jobs before building a manifest. Keep the source/config snapshots,
raw inputs/results, command receipts, environment and manifest together. Changes
or deletions are detected by the verifier. Manifest creation refuses to overwrite
existing evidence. The original `daahe audit` command continues to check for
original-author artifacts and can correctly remain blocked after a successful
independent experiment.

The delivered campaign retains the source that actually generated its raw
records. The current verifier additionally supports `--jobs 4` for independent
raw-log recomputation, without rerunning the network. A full optional network
replay refuses local source drift, including later verifier-only edits. To use
the preserved implementation after unpacking the full evidence archive:

```bash
CAMPAIGN="$PWD/evidence/independent/simulation"
PYTHONPATH="$CAMPAIGN/source/src" python \
  "$CAMPAIGN/source/tools/verify_simulation_campaign.py" "$CAMPAIGN" --replay
```

This optional command reruns all 140 network cases and can be expensive. The
delivered full-raw verification receipt is separate from this optional replay.

CI executes functional tests and exposes a manually requested complete campaign.
CI artifacts are new runs; the presence of a workflow alone is not execution
evidence. Actual local receipts are delivered separately from future CI runs.
