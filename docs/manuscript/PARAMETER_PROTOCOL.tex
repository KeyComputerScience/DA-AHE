\paragraph{Parameters and encoding.}
DA-AHE operates over $R_q=\mathbb{Z}_q[X]/(X^d+1)$ and
$R_p=\mathbb{F}_p[X]/(X^d+1)$, with the fixed parameter tuple
\begin{equation}
 \begin{aligned}
 &(k,d,n,m,q,p,\lambda_{\mathrm{tag}})\\
 &\quad=(6,256,1536,1536,2^{32},65537,16),\quad n=kd.
 \end{aligned}
 \label{eq:daahe_protocol_parameters}
\end{equation}
Here $m$ is the estimator's flattened-LWE sample-count input, not a claim that
all ring-structured rotations are independent public-key samples.
$\lambda_{\mathrm{tag}}$ is the number of authentication coefficients, rather
than a bit-security parameter.
Let $[\cdot]_v$ denote coefficient-wise reduction modulo $v$, and let
$\operatorname{ctr}_v$ select centered integer representatives.
$\operatorname{Lift}_p$ embeds these centered plaintext coefficients into $R_q$.
The plaintext
scaling factor satisfies
\begin{equation}
 \Delta=\lfloor q/p\rfloor=65535,\qquad q=p\Delta+1.
 \label{eq:daahe_protocol_scaling}
\end{equation}
The public matrix $A\in R_q^{k\times k}$ is expanded deterministically from a
256-bit public seed. Key generation samples $\boldsymbol{s},\boldsymbol{e}$
at $\sigma_{\mathrm{key}}=3.2$ and publishes
$\boldsymbol{b}=[A\boldsymbol{s}+\boldsymbol{e}]_q$. For plaintext
$M_i\in R_p$, encryption samples
$\boldsymbol{r}_i,\boldsymbol{e}_{1,i},e_{2,i}$ using the selected profile's
$\sigma_{\mathrm{enc}}\in\{3.2,3.4,3.6\}$ and computes
\begin{equation}
 \begin{aligned}
  \boldsymbol{u}_i&=[A^{\mathsf T}\boldsymbol{r}_i+
                       \boldsymbol{e}_{1,i}]_q,\\
  v_i&=[\boldsymbol{b}^{\mathsf T}\boldsymbol{r}_i+e_{2,i}
             +\Delta\operatorname{Lift}_p(M_i)]_q,\\
  c_i&=(\boldsymbol{u}_i,v_i).
 \end{aligned}
 \label{eq:daahe_protocol_encryption}
\end{equation}
The reference sampler uses finite, 256-bit-quantized cumulative distribution
tables on $[-\lceil16\sigma\rceil,\lceil16\sigma\rceil]$, with independent
draws. Its correctness calculation is distinct from the estimator's Gaussian
input model. The selected seven-attack flattened-LWE execution reports a
minimum estimated operation cost of $136.475$ bits under its recorded models;
$128.1$ bits is the requested estimator threshold. Lattice-reduction attacks
use the recorded ADPS16 quantum cost model, while coded-BKW retains its native
operation-count model. This heuristic analysis does not establish a
module-specific, finite-sampler, implementation or worst-case security proof.
Changing $\sigma_{\mathrm{enc}}$ changes ephemeral noise and decoding capacity;
it does not define an ordered long-term cryptographic-security level.

The canonical ciphertext contains $(k+1)d$ little-endian 32-bit words, hence
\begin{equation}
 |c_i|=(k+1)d\cdot4=7168\ \text{bytes}.
 \label{eq:daahe_protocol_ciphertext_bytes}
\end{equation}
Packing at most $240$ data coefficients and $16$ authentication coefficients
uses one plaintext polynomial. The uncompressed $480$ data coefficients and
$16$ authentication coefficients require two polynomials, or $14336$ ciphertext
bytes. Thus single-polynomial packing reduces the protected ciphertext payload
by $50\%$. Tickets, block tags, transport headers and retries have separate
costs, so this percentage is not a claim about complete wire traffic.

\paragraph{Actions, allowlisted profiles and authorization.}
The controller selects indivisible library rows
$\boldsymbol{a}_t=[\rho_t,\delta_{Q,t},N_t,L_{\mathrm{blk},t},r_t,\ell_t]^{\mathsf T}$.
The row binds sampling, quantization, maximum group size, block length, repair
intensity and an immutable profile. Components are not recombined independently
online. $N_t$ is a maximum authorized group size; the actual batch roster has
$M_B$ members. A profile $\Pi_B$ fixes the ordered support
$S_{\Pi_B}=(s_0,\ldots,s_{L_B-1})\subseteq\{0,\ldots,479\}$,
$L_B\leq240$, the transform version, quantization rule, coefficient bound
$B_x(\Pi_B)$, noise setting, capacity $N_{\max}(\Pi_B)$ and integrity policy.
Its 96-bit profile identifier is an index; the full 256-bit profile digest is
also bound to authorization and checked against the local allowlist.

The fallback is identified by its complete configured action row and profile
digest. Write
\begin{equation}
 \begin{aligned}
 \boldsymbol{a}_{\mathrm{fb}}
 &=[\rho_{\mathrm{fb}},\delta_{Q,\mathrm{fb}},N_{\mathrm{fb}},
          L_{\mathrm{blk},\mathrm{fb}},r_{\mathrm{fb}},\ell_{\mathrm{fb}}]^{\mathsf T},\\
 \Pi_{\ell_{\mathrm{fb}}}&=\Pi_{\mathrm{fb}}.
 \end{aligned}
 \label{eq:daahe_protocol_fallback}
\end{equation}
The index $\ell_{\mathrm{fb}}$ selects the full digest-bound
$\Pi_{\mathrm{fb}}$ from that same library. A singleton action
$[0.50,16,1,64,0,\ell_{\mathrm{fb}}]^{\mathsf T}$ may be configured with
$L=120$ and quantization step $16$; its $\sigma_{\mathrm{enc}}$ and
$N_{\max}$ must come from the selected profile, with $1\leq N_{\max}$.
The controller uses its actual configured row, which need not have singleton
capacity. Display names do not establish row identity or feasibility.
Allowlisting and numerical checks do not constitute external
resource or control certification. Deployment additionally requires reviewed
workspace, airtime, uncertainty and fallback evidence; absence of admissible
actions causes fail-closed operation. No nonempty safe-action set or invariant
operating domain is inferred from the reference library alone.

For batch $B$, the sink constructs a canonical ticket body
\begin{equation}
 \begin{aligned}
  T_B={}&(\mathrm{ver}=2,e,B,\mathrm{CID},\mathrm{ProfileID},\\
       &\quad H_{\Pi_B},\mathcal{I}^{\star}_B,n_B,
                L_{\mathrm{blk},B},\boldsymbol{\theta}_{\mathrm{enc}}),\\
  \mathcal{I}^{\star}_B={}&((\mathrm{ID}_i,N_i))_{i=1}^{M_B},\\
  D_B={}&\operatorname{SHA3\!\text{-}\!256}(\operatorname{Encode}(T_B)),\\
  \sigma_B={}&\operatorname{Sign}_{sk_S}
                   (\operatorname{Frame}_{T}(\mathrm{dom}_{\mathrm{ticket}},D_B)),\\
  \widehat{T}_B={}&(T_B,\sigma_B).
 \end{aligned}
 \label{eq:daahe_protocol_ticket}
\end{equation}
$\operatorname{Encode}$ is the canonical ticket-body encoding;
$\boldsymbol{\theta}_{\mathrm{enc}}$ contains the complete encryption parameter
tuple. The roster is nonempty, canonically ordered and contains distinct source
identifiers, each with its authorized 128-bit nonce $N_i$. The batch nonce
$n_B$ is 256 bits. The ticket fixes $L_{\mathrm{blk},B}\in\{32,64\}$ and
\begin{equation}
 M_B\leq\min\{N_t,N_{\max}(\Pi_B)\},\qquad
 M_B B_x(\Pi_B)\leq(p-1)/2.
 \label{eq:daahe_protocol_roster_capacity}
\end{equation}
Sources and the sink compare the ticket parameters with their actual keys.
Provisioning must bind the context and epoch to the intended public-key
fingerprint and policy configuration; equality of parameter tuples alone does
not identify a key. The reference ticket provider uses ML-DSA-44. A new sample
or key configuration requires fresh authorization, including a fresh signed
batch nonce; re-signing the same body does not create a new batch identity.

\paragraph{Coefficient authentication and exact source emission.}
The 256-bit epoch secret $r_e$ derives domain-separated HMAC-SHA3-256 subkeys
$\kappa_{K,e}$ and $\kappa_{\xi,e}$. Domain-separated HMAC outputs, followed by
counter-framed SHAKE256 expansion and unbiased 32-bit rejection sampling into
$\mathbb{F}_p$, define
\begin{equation}
 \begin{aligned}
  s_{K,B}&=F_{\kappa_{K,e}}
       (\mathrm{dom}_K,D_B,\operatorname{EncLen}(L_B)),\\
  s_{\xi,i,B}&=F_{\kappa_{\xi,e}}
       (\mathrm{dom}_{\xi},D_B,\operatorname{EncID}(\mathrm{ID}_i),N_i),\\
  K_B&=\operatorname{Mat}_{\lambda_{\mathrm{tag}}\times L_B}
      (\operatorname{Expand}_{\mathbb{F}_p}
               (s_{K,B},\lambda_{\mathrm{tag}}L_B)),\\
  \xi_{i,B}&=\operatorname{Expand}_{\mathbb{F}_p}
               (s_{\xi,i,B},\lambda_{\mathrm{tag}}).
 \end{aligned}
 \label{eq:daahe_protocol_derivation}
\end{equation}
Here $F$ denotes the implementation's framed HMAC derivation, not SHAKE alone.
Protocol framing $\operatorname{Frame}_T$ prefixes each byte field with a
32-bit little-endian length; derivation framing prefixes fields with 64-bit
big-endian lengths and uses a typed source identifier. The exact domains,
encodings and rejection stream are fixed by the implementation.

For two synchronized integer-valued channels, let
$z_i=\operatorname{IntDb2}(m_i^{(1)})\Vert\operatorname{IntDb2}(m_i^{(2)})$
and
\begin{equation}
 \begin{aligned}
  \widetilde{x}_{i,h}&=\operatorname{Round}_{\mathrm{away}}
               (z_i[s_h]/\delta_{Q,B}),\qquad
               |\widetilde{x}_{i,h}|\leq B_x(\Pi_B),\\
  x_i&=[\widetilde{x}_i]_p,\qquad
  t_i=[K_Bx_i+\xi_{i,B}]_p,\\
  M_i(X)&=\sum_{h=0}^{L_B-1}x_{i,h}X^h+
          \sum_{j=0}^{\lambda_{\mathrm{tag}}-1}t_{i,j}X^{L_B+j}.
 \end{aligned}
 \label{eq:daahe_protocol_packing}
\end{equation}
Quantization rounds nearest with ties away from zero and rejects bound
violations. The reference transform uses two integer-lifting levels, periodic
boundaries and profile-bound dyadic coefficients. Fixed support is obtained from
the allowlisted profile whose full digest is signed; it needs no per-report position bitmap.
The remaining plaintext coefficients are zero.

For each $(D_B,\mathrm{ID}_i,N_i)$, a durable source ledger first binds the
SHA3-256 digest of the canonical \emph{raw-channel snapshot}, then stores the
first completed envelope before releasing it. Different raw snapshots are
rejected even if quantization would make their coefficient vectors equal.
Concurrent callers with the same snapshot may construct internal candidates,
but only the atomically committed winner is released. Retries return its exact
ticket signature, ciphertext blocks and MACs. A crash before caching permits
the same snapshot to resume without releasing an uncached candidate; a crash
after caching preserves exact retransmission. Database rollback/deletion and
key-state rollback must be prevented by deployment storage. This condition
prevents two distinct emitted reports from reusing one affine-tag offset:
otherwise $2c_1-c_2$ could authenticate $2x_1-x_2$ under that same offset.

For block $C_{i,j}$, $J_B=7168/L_{\mathrm{blk},B}$, the source computes
\begin{equation}
 \begin{aligned}
  m^{\mathrm{blk}}_{i,j}&=\operatorname{Frame}_T
  (\mathrm{dom}_{\mathrm{blk}},D_B,\operatorname{UTF8}(\mathrm{ID}_i),\\
  &\hspace{17mm}N_i,\operatorname{Enc32}(j,J_B),C_{i,j}),\\
  \tau_{i,j}&=\operatorname{Trunc}_{128}
                    (\operatorname{HMAC}_{w_{i,e}}(m^{\mathrm{blk}}_{i,j})).
 \end{aligned}
 \label{eq:daahe_protocol_block_mac}
\end{equation}
Transport MAC keys contain at least 256 bits. The gateway transport MAC is
the full HMAC-SHA3-256 of
\begin{equation}
 \begin{aligned}
 m^{\mathrm{agg}}_B={}&\operatorname{Frame}_T
       (\mathrm{dom}_{\mathrm{agg}},D_B,\sigma_B,\\
       &\quad\operatorname{Encode}(\mathcal{I}_{\mathrm{recv}}),
                                    \operatorname{Serialize}(c_B)).
 \end{aligned}
 \label{eq:daahe_protocol_aggregate_frame}
\end{equation}
Gateway-held MAC keys support transport filtering at uncompromised gateways;
end-to-end integrity additionally relies on the signed roster, hidden affine
authenticator, source single-emission rule and sink replay protection under the
trusted-source/sink assumptions.

\begin{algorithm}[t]
\caption{Single-Ciphertext Profile-Bound Encapsulation}
\label{alg:combine_LWE}
\small
\begin{algorithmic}[1]
\Require Raw channels $m_i$; signed ticket $\widehat{T}_B$; source $(\mathrm{ID}_i,N_i)$;
 public key $pk_e$; epoch secret $r_e$; block key $w_{i,e}$; signature verifier,
 profile allowlist and durable $\mathsf{SourceEmissionStore}$
\Ensure One cached authenticated envelope $\mathcal{C}_i$, or $\bot$
\State Verify ticket signature, full profile digest, capacity and data no-wrap;
 obtain $\Pi_B$ and $D_B$; on failure return $\bot$
\State Require the exact source entry in $\mathcal{I}^{\star}_B$,
 matching key/ticket parameters, and a compressed profile with
 $L_B\leq240$, $\lambda_{\mathrm{tag}}=16$ and integrity enabled
\State Snapshot raw $m_i$; encode $\widetilde{x}_i$ and check its coefficient bounds
\State $d_i\gets\operatorname{SHA3\!\text{-}\!256}(\operatorname{CanonicalJSON}(m_i))$;
 $\iota_i\gets(D_B,\mathrm{ID}_i,N_i)$
\State $J_B\gets7168/L_{\mathrm{blk},B}$
\State Atomically bind $(\iota_i,d_i)$ and commit; reject a conflicting raw digest
\If{a completed envelope is already cached}
 \State Validate its structure and original signed ticket; return those exact cached bytes
\EndIf
\State Derive $K_B,\xi_{i,B}$; compute $x_i,t_i,M_i$ by
 \eqref{eq:daahe_protocol_packing}
\State $c_i\gets\operatorname{Enc}_{\Pi_B}(pk_e,M_i)$
\State Enumerate canonical ciphertext blocks $C_{i,0},\ldots,C_{i,J_B-1}$
\For{$j=0,\ldots,J_B-1$}
 \State Compute $\tau_{i,j}$ using \eqref{eq:daahe_protocol_block_mac}
\EndFor
\State Form candidate $\mathcal{C}_i=(\widehat{T}_B,(\mathrm{ID}_i,N_i),
                          \{(j,J_B,C_{i,j},\tau_{i,j})\}_{j=0}^{J_B-1})$
\State Atomically cache-first-wins under $(\iota_i,d_i)$ and commit before release
\State Read and validate the winning cached envelope; return its exact bytes
\Statex Any error, storage failure or malformed cached entry returns $\bot$;
 no uncached candidate is released
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{Exact-Roster Authenticated Aggregation}
\label{alg:agg}
\small
\begin{algorithmic}[1]
\Require Signed ticket $\widehat{T}_B$; source envelopes; block keys $\{w_{i,e}\}$;
 gateway key $w_{g,e}$; signature verifier and profile allowlist
\Ensure Aggregate envelope $\mathcal{C}_B$, or $\bot$
\State Verify ticket signature, full profile digest, capacity and no-wrap;
 require a one-polynomial integrity-enabled profile
\State $J_B\gets7168/L_{\mathrm{blk},B}$;
 initialize a zero aggregate-word array and $\mathcal{I}_{\mathrm{recv}}\gets()$
\For{each $(\mathrm{ID}_i,N_i)$ in the signed canonical roster}
 \State Read the next source envelope; reject missing, duplicate, out-of-order
 or unauthorized sources, a different signed ticket, or a block count other than $J_B$
 \For{$j=0,\ldots,J_B-1$}
  \State Require block index $j$, total $J_B$ and exact payload length $L_{\mathrm{blk},B}$
  \State Verify $\tau_{i,j}$ before using its payload; on failure return $\bot$
  \State Add its canonical 32-bit words into the corresponding accumulator positions modulo $q$
 \EndFor
 \State Append $(\mathrm{ID}_i,N_i)$ to $\mathcal{I}_{\mathrm{recv}}$
\EndFor
\State Reject extra envelopes or $\mathcal{I}_{\mathrm{recv}}\neq\mathcal{I}^{\star}_B$
\State Serialize the $7168$-byte $c_B$ and form the exact aggregate transport message
\State Compute its full HMAC-SHA3-256 tag $\tau_{g,B}$ using $w_{g,e}$
\State \Return $\mathcal{C}_B=(\widehat{T}_B,\mathcal{I}_{\mathrm{recv}},c_B,\tau_{g,B})$
\Statex Any failure aborts the whole batch; no partial aggregate is released
\end{algorithmic}
\end{algorithm}

\paragraph{Decoding and approximate signal reconstruction.}
For $c_B=\sum_{i\in\mathcal{I}^{\star}_B}c_i\pmod q$, define
$w_B=[v_B-\boldsymbol{s}^{\mathsf T}\boldsymbol{u}_B]_q$. The reference decoder
uses exact integer arithmetic:
\begin{equation}
 \operatorname{Dec}_{sk_e}(c_B)_h
 =\left[\left\lfloor
 \frac{\operatorname{ctr}_q(w_{B,h})+\lfloor\Delta/2\rfloor}{\Delta}
 \right\rfloor\right]_p.
 \label{eq:daahe_protocol_decoder}
\end{equation}
Here $E_h$ is the $h$th coefficient, before reduction modulo $q$, of the
shared-key aggregate noise
\begin{equation}
 E_B=\boldsymbol{e}^{\mathsf T}\sum_i\boldsymbol{r}_i
       -\boldsymbol{s}^{\mathsf T}\sum_i\boldsymbol{e}_{1,i}
       +\sum_i e_{2,i}.
 \label{eq:daahe_protocol_aggregate_noise}
\end{equation}
Because $q=p\Delta+1$, writing a sum of centered plaintext lifts as
$S_h=\operatorname{ctr}_p([S_h]_p)+p g_h$ gives the effective error
$E_h-g_h$, with $|g_h|\leq\lceil M_B/2\rceil$. The finite-CDT bound includes
this scaling carry. Data no-wrap in \eqref{eq:daahe_protocol_roster_capacity}
is a separate condition for interpreting decoded data sums as signed integers;
authentication coefficients are intentionally summed in $\mathbb{F}_p$.
Decoding alone does not authenticate a report or detect every margin violation.

After verifying the aggregate tag and data bound, the sink dequantizes the
decoded data sum, scatters it at the signed ordered support and sets omitted
positions to zero. It applies the inverse integer transform separately to the
two 240-coefficient channels. The result approximates the physical sum:
integer lifting with rounding, selection and quantization do not generally
commute with summation. Exact encrypted coefficient aggregation therefore does
not imply exact physical-signal aggregation or a universal distortion bound.

\begin{algorithm}[t]
\caption{Sink Verification and Single-Polynomial Unpacking}
\label{alg:sink}
\small
\begin{algorithmic}[1]
\Require Aggregate envelope $\mathcal{C}_B$; sink decryption key $sk_e$;
 epoch secret $r_e$; gateway key $w_{g,e}$; active epoch/context;
 signature verifier, profile allowlist and durable $\mathsf{Seen}$ store
\Ensure Authenticated coefficient sum and reconstructed channels, or $\bot$
\State Parse $(\widehat{T}_B,\mathcal{I}_{\mathrm{recv}},c_B,\tau_{g,B})$;
 require active epoch/context and matching ticket/key parameters
\State Verify signature, full allowlisted profile digest, capacity and no-wrap;
 require compressed, integrity-enabled $\Pi_B$
\State Require $\mathcal{I}_{\mathrm{recv}}=\mathcal{I}^{\star}_B$ and exactly $7168$ ciphertext bytes
\State Verify the full gateway transport MAC over the exact signed ticket,
 contributor tuple and ciphertext
\State Deserialize canonical words and decode by \eqref{eq:daahe_protocol_decoder}
\State Unpack $(\widehat{x}_B,\widehat{t}_B)$ at lengths
 $(L_B,\lambda_{\mathrm{tag}})$; reject nonzero unused plaintext positions
\State Derive $K_B$ and
 $\Xi_B\gets[\sum_{(\mathrm{ID}_i,N_i)\in\mathcal{I}^{\star}_B}\xi_{i,B}]_p$
\If{$\widehat{t}_B\neq[K_B\widehat{x}_B+\Xi_B]_p$}
 \State \Return $\bot$
\EndIf
\State $\widetilde{x}_B\gets\operatorname{ctr}_p(\widehat{x}_B)$;
 reject any $|\widetilde{x}_{B,h}|>M_B B_x(\Pi_B)$
\State $\widehat{z}_B\gets\operatorname{Scatter}
       (\delta_{Q,B}\widetilde{x}_B,S_{\Pi_B},480)$
\State $\widehat{m}^{(1)}_B\gets\operatorname{IntDb2}^{-1}(\widehat{z}_B[0{:}239])$;
 $\widehat{m}^{(2)}_B\gets\operatorname{IntDb2}^{-1}(\widehat{z}_B[240{:}479])$
\State Atomically insert $D_B$ into $\mathsf{Seen}$ and commit;
 reject an existing identifier or a storage failure
\State \Return $(\widetilde{x}_B,\widehat{m}^{(1)}_B,\widehat{m}^{(2)}_B)$
\Statex All failed checks return the same rejection outcome; no plaintext is released before the commit
\end{algorithmic}
\end{algorithm}

The sink records $D_B$ only after validation and reconstruction, so an invalid
candidate cannot consume an unused batch identifier. The unique committed
insert supplies at-most-once acceptance under persistent, rollback-protected
storage. A crash after commit but before application delivery can lose a result;
durable application delivery additionally requires a transactional result/outbox
and an idempotent consumer. Uniform rejection is an API property; the Python
implementation makes no constant-time claim.

The host implementation materializes ciphertext objects and complete source
envelopes, including a durable retransmission cache. Its block iterator emits
canonical words through a 32- or 64-byte buffer, and gateway word addition can
be performed block by block with a complete aggregate accumulator. These
interfaces do not establish complete embedded buffer lifetimes or a
10-KiB workspace certificate. Such a deployment claim requires the complete
linked implementation and role-specific resource evidence.

The archived finite-CDT calculation covers $42$ declared $(\sigma_{\mathrm{enc}},N)$
choices and at most two plaintext polynomials. For one choice made before the
batch's fresh honest noises, its outward probability upper endpoint is
$U\approx5.15849649769099\times10^{-40}$. This is a joint random-key,
history and fresh-noise probability, rather than a bound conditioned on every
fixed key or arbitrary realized history. For a predeclared mission cap of
$B_{\mathrm{mis}}$ fresh-noise batch attempts, let $\mathcal{F}_{\mathrm{mis}}$
denote any covered decoding failure during that mission. Then
\begin{equation}
 \Pr(\mathcal{F}_{\mathrm{mis}})\leq\min\{1,B_{\mathrm{mis}}U\}.
 \label{eq:daahe_protocol_mission_budget}
\end{equation}
This union bound does not assume independent batch outcomes. With the archived
exact rational endpoint, a target of $2^{-128}$ permits at most five attempts;
a target of $2^{-120}$ permits $1458$. Fresh-noise retries consume attempts.
Selection of source subsets after inspecting current-batch ciphertexts/noises
is outside the bound. These correctness budgets do not supply an unlimited
lifetime, malicious-ciphertext or full-system safety guarantee. Parameter and
bound provenance are specified in Appendix~\ref{subsec:lwe_reproducibility}.
