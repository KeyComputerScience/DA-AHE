# 落地接口与验收

主机参考实现暴露 `encapsulate → aggregate → Sink.accept`，控制侧暴露
`select → apply → observe`。
`integration.issue_decision_ticket` 提供此绑定：默认要求严格认证决策，复查硬约束，
核对真实 Profile 摘要、量化和容量，再把动作摘要与 M-LWE 公钥指纹绑定到 context。
`ablations.py` 保留静态/无修复对照的约束。

## 数据面接入

1. 采集端统一两通道单位、整数尺度、采样窗口和时间同步；超过量化范围立即拒绝，
   不静默饱和。。
2. 管理面预置不可变完整 Profile 摘要、配置/动作版本、sink ML-DSA 公钥和当前纪元。
3. 仅向受信任源和 sink 配置 epoch root。网关只持各源分块密钥与网关传输密钥。
   所有用途的对称密钥独立派生，不在日志或仓库中存储原始密钥。
   源端还须提供持久 `SourceEmissionStore`：同票据/源/nonce 绑定同一个原始采样窗口。
4. 网关入口先检查票据、当前纪元/上下文和名单，再接收分块；重复/缺失/错误块不能
   产生部分成功的聚合。
5. sink 使用持久 SQLite Seen，成功写入后才释放结果。数据库与纪元状态须防回滚、
   备份和访问控制；重启不能清空 Seen。
   当前 Seen 只提供至多一次接受；提交后、应用取到结果前掉电仍会丢失结果投递。
   长期部署还需把结果/outbox与Seen同事务持久化，并由可信应用幂等取回。
6. 失败返回统一拒绝结果；不要把内部标签、解密值或失败原因透传到不受信任网络。

轻量路径只提供受信任网关下的明文认证聚合。调用层负责纪元、上下文和持久防重放；
不要把它宣传为抗恶意网关的端到端聚合完整性。敏感性分类器和30/70负载是外部策略。

## 控制与网络接入

每个1秒控制区间只使用当前和过去的队列、残余丢包、延迟、BER、异常、篡改和噪声指标。
`a_t` 用于下一段网络运行；网络驱动应落实采样、量化、批次、分块和路由修复动作。

Strict SafetyFilter 验证完整动作、profile和部署摘要，内存/airtime/no-wrap/
decoding/noise/security材料，及当前状态域。鲁棒控制还需独立的校准误差和fallback证书。

## 板端接入

`embedded/daahe_core.c` 是完整的便携算术/分块累加核心，不是 Contiki 固件。
在真正的 nRF52840 工程中接入 vetted SHA3/HMAC、ML-DSA、CSPRNG、高斯采样器、
数据采集、radio和RPL栈。原始固件缺失，

验收保存：最终ELF/map、text/data/bss、每角色stack高水位、每操作周期计数、
互斥CPU/TX/RX/idle驻留时间、供电电压/电流、重传与完整头部长度。10KiB是特定
action workspace预算。
